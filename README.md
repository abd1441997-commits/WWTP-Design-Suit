# Industrial WWTP Design Suite — mobile app (Android + iOS + PWA)

App ID: `com.elwishy.wwtpdesign` · Name: **Industrial WWTP Design Suite** · Built with Capacitor 8 (native shell) around the original HTML/JS engineering tool.

```
www/                    the app (HTML/CSS/JS, fonts, jsPDF) - runs in browser, PWA and native shell
  js/engine.js          ORIGINAL engineering formulas, extracted unchanged (see tests/golden.json)
  js/ui.js              original UI + validation hooks + design-check layer
  js/validate.js        range rules for every numeric input
  js/store.js           project persistence (Preferences on device, localStorage in browser)
  js/projects.js        project & profile UI, project manager sheet
  js/pdf.js             real vector PDF report (works offline / inside WebViews)
  js/native.js          Capacitor bridge: share sheet, back button, keyboard, lifecycle
  sw.js, manifest.webmanifest, icons/   PWA files (sw.js is generated by `npm run build`)
android/  ios/          native projects (generated by Capacitor, icons + splash included)
assets/                 icon & splash sources (regenerate: npm run assets, then npx capacitor-assets generate)
tests/                  automated tests (+ golden.json from the ORIGINAL app) and e2e scripts
.github/workflows/      build.yml (tests + Android + iOS), pages.yml (publish PWA)
```

## 1. What was verified (and what was not)

**Executed and passing in the build environment**
- `npm test` — 26 automated checks: the engineering results of 14 scenarios (flow, strength, every optional unit/alternative, RO, minimal train…) are **identical to the original app** (stage-by-stage tables, mass balance, final stream); input validation; engineering guards; persistence (restart, export→import, damaged/hostile files, multi-project).
- Real Chromium end-to-end (`tests/e2e/browser.py`): bundled fonts load, app reloads **offline** through the service worker, edits made offline persist, invalid input is rejected in the UI, **PDF export produces a valid 14-page PDF** (selectable text, no blank pages), phone-width layout has no horizontal overflow.
- Native-bridge simulation (`tests/e2e/native_sim.py`): with mock Capacitor plugins the app saves/restores through *Preferences*, writes the PDF through *Filesystem* and opens *Share*, and handles the Android back button. This is a simulation of the plugin calls, **not** a device test.
- Android and iOS projects generated, synced with the web app, app ID/icons/splash applied; `npm audit` for runtime dependencies: 0 vulnerabilities; workflow YAML parses.

**NOT done / not verifiable here — you must do these**
- No APK, AAB or IPA has been built. The sandbox cannot download the Android SDK/Gradle and has no macOS/Xcode. The Gradle signing edit (`android/app/build.gradle`) and both GitHub workflows have never been run.
- Nothing has been tested on a physical Android phone or iPhone: share sheet, file picker for import, keyboard resizing, notch/status-bar insets, splash screen, PDF opening on the device. Use `docs/TESTING.md`.
- The `macos-26` runner label and `xcode-version: latest-stable` in `build.yml` are assumptions about GitHub's current images — adjust if the first iOS run complains.

## 2. How the engineering was protected
- Formulas live in `www/js/engine.js`, extracted byte-for-byte from the original. `tests/golden.json` was generated from the original single-file app; `npm test` fails if any number changes.
- New safety layer (does not touch formulas): every input is range-checked (`validate.js`); the aeration stage refuses to size when the BOD target is not below the incoming BOD and blocks dependent units; any stage that yields division-by-zero/NaN/∞ or negative values is flagged in its card and in a **Design Checks** panel (also printed in the report/PDF); cross-checks warn about COD < BOD, extreme pH, disabled settling tank, etc.
- Yellow fields = values you entered; table values = calculated. Saved projects are re-validated on load, so a damaged or hand-edited file can never feed invalid numbers into the engine.
- Hydraulic profile remains **schematic** (typical per-unit head losses) as in the original — verify against site levels.

## 3. Saving
- Autosave ~0.5 s after every change and when the app is backgrounded. Last project reopens automatically.
- **Projects** button (header): new, open, duplicate, delete, save a copy, **Export** (`.wwtp.json`, shared via the system share sheet) and **Import**. Export regularly: app data is lost if the app is uninstalled or the phone's data is cleared.
- Project info (name, client, site, number, revision, notes) and your profile (name, department) appear on the report cover and PDF.

## 4. Local development
```
npm ci
npm run build          # copies jsPDF + fonts into www/, regenerates sw.js
npm test               # engineering + validation + persistence tests
```

## 5. Install on your Android phone

**Easiest — no accounts, no tools on your PC (GitHub Actions):**
1. Create a free GitHub account → New repository (private is fine) → upload this whole folder (or `git push`).
2. Open the repo → **Actions** → *Build & test* → wait for the green run (~10 min the first time).
3. Open the run → **Artifacts** → download `WWTP-Design-Suite-android-debug-apk` (a zip containing `app-debug.apk`).
4. Send the APK to your phone (Drive/Telegram/USB), tap it, allow “install unknown apps” for that app when asked, install. Open **Industrial WWTP Design Suite**.
   (A debug-signed APK is fine for your own use; to update later, install the newer APK over it.)

**Signed release APK + Play Store bundle (AAB):**
1. Run once: `scripts/create-keystore.sh` (needs Java's `keytool`). **Back up the .jks file and the passwords — all future updates must use the same key.**
2. GitHub repo → Settings → Secrets and variables → Actions → add: `ANDROID_KEYSTORE_BASE64` (output of `base64 -w0 wwtp-release.jks`), `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`.
3. Re-run the workflow → artifact `WWTP-Design-Suite-android-release` contains the signed `app-release.apk` and `app-release.aab`.
4. Google Play: create a Play Console developer account (one-time **US$25**), create the app, upload the `.aab` to Internal testing, fill the store listing, content rating and Data safety form (this app collects no data and makes no network requests). Check Google's current testing requirements for new developer accounts before planning a public release date.

Local alternative: open `android/` in Android Studio → Build → Generate Signed Bundle/APK.

## 6. iOS — what is required to publish
Needs: **Apple Developer Program membership (US$99/year)** and a signing identity. A Mac is *not* strictly required if you use the GitHub macOS runner, but it makes setup and testing much easier (Xcode/Simulator are Mac-only).
1. Enroll at developer.apple.com. Register the App ID `com.elwishy.wwtpdesign`.
2. App Store Connect → My Apps → **+** → New App (same bundle ID, name *Industrial WWTP Design Suite*).
3. Create an **Apple Distribution** certificate (export as `.p12` with a password) and an **App Store** provisioning profile for the bundle ID.
4. GitHub secrets: `APPLE_CERT_P12_BASE64`, `APPLE_CERT_PASSWORD`, `APPLE_PROVISION_PROFILE_BASE64`, `APPLE_TEAM_ID`; for TestFlight upload also `APP_STORE_CONNECT_KEY_ID`, `APP_STORE_CONNECT_ISSUER_ID`, `APP_STORE_CONNECT_KEY_P8_BASE64` (App Store Connect → Users and Access → Integrations → API key).
5. Run the *Build & test* workflow manually (**Run workflow**, tick *upload_testflight*) → the signed `.ipa` is built and uploaded; it appears in TestFlight after Apple's processing. Add yourself as an internal tester and install through the TestFlight app.
6. App Store release: screenshots, description, privacy policy URL (state that no data leaves the device), age rating, then *Submit for review*. Encryption export question is pre-answered (`ITSAppUsesNonExemptEncryption = false`).
Without a paid account you can still run the app on **your own** iPhone from Xcode on a Mac (free provisioning, expires every 7 days).

## 7. PWA (installable web version, no store)
Push to GitHub → repo Settings → Pages → Source: *GitHub Actions*. `pages.yml` publishes `www/` over HTTPS. Open the URL on the phone → Android Chrome: menu → *Install app*; iPhone Safari: Share → *Add to Home Screen*. Works offline after the first load. Limits vs native app: no store listing, iOS may clear PWA storage after weeks of non-use (use Export for backups), file sharing depends on the browser.
